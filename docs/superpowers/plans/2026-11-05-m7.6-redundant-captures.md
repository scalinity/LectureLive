# M7.6 — Redundant captures and storage cleanup

## Context

During class, auto-capture takes every reveal of a build slide, every fade frame, every re-shown slide, and, once the share
ends, the classroom camera. Biostat Week 12 (`$HOME/Documents/AIBHS/Biostatistics for AI/Weeks/Week 12 — Survival Analysis`)
produced 236 captures. 131 were discarded by hand during the lecture, and the 105 kept still included partials and 22 camera
frames, which the stop snapshot embedded in the notes. The notes step (§6.2) must embed every slide it is sent, so junk that
reaches a snapshot always lands in the Markdown.

The goal is that no image has to be discarded by hand and nothing redundant reaches the model. It is done without an LLM:
no extra cost and no second pass over the images. Once a lecture's study page is finished, its images, its discarded
images and its recordings are deleted. Older weeks are brought up to the same state.

### Evidence (pixel analysis of Week 12, 256×144 grayscale, every capture against its neighbours)

| Pattern | Count | Cause |
|---|---|---|
| Build step / fade frame of a later capture | 109 of 131 discards | A change where the earlier frame was blank page is new content. "Lost" pixels (changed where the earlier frame had structure) are ≤ 0.25 % of the frame. Chains run 2–7 steps over up to ~2.5 min and are not always monotonic (101 table only, 102 faint fade, 103 complete). |
| Classroom camera after the share | 22, kept and embedded | soft 0.48–0.55 and dominant 0.13–0.14 (camera calibration: 0.41–0.48 / 0.15–0.17). `scene::classify` needs `moving`, and a still room between movements reads as a slide (`scene.rs:101`). |
| Re-shown slide | ~8 (13 = 28, 16 = 31, 85 = 136) | The detector's same-slide rule looks back only 60 s (`RECENT_SAMPLES`). |
| Cursor / PowerPoint slideshow toolbar twin | a few (209/210, 214/215) | Small icons at the bottom-left (~14 % × 4.5 %) and the pointer, drawn when the presenter moves the mouse. |
| Content judgement (old Module 9 slides 11 and 46, "Thank You", a Windows desktop) | ~6 | Not decidable from pixels; remains a manual ×. |
| Manual mistakes | 2 | Kept partial 94 / 191; discarded the complete 95 / 192. |

Other classes: build steps are 0–3 % of captures (Biostat W08: 12 %); re-shows are 5–18 % (Applied GenAI W10: 14 of 80).
Storage: recordings 2.5 GB, slides 275 MB, pages 103 MB. M7.4's sweep (22 Oct) already cleared 262 files from
finished weeks.

### Decisions (the person's answers)

- No LLM filter; the OpenAI key is not needed.
- **Recordings are deleted** once a lecture's study page is finished (the lectures are available online).
- **All six older weeks are rebuilt** (Biostat W08, Fundamentals W05/W06/W08, Applied GenAI W05/W07), about $3–6 in page
  requests, and then cleared.
- **Week 12: swap 94→95 and 191→192.** Elsewhere tidy never overrides a manual removal or a manual capture.
- Discarded images are deleted once the page is finished. They are no longer kept in the page's hidden `removed-captures`
  archive, so ⌘Z for them ends there.

## Design

### 1. Comparison — `crates/core/src/capture/compare.rs` (new, pure)
- `Look { gray: GrayImage /*256×144*/, flat: bitset, ink: u32, features: scene::Features }`, built through
  `detect::thumb(&rgba, &Region::WHOLE)`. That is the detector's own size, so the thresholds and `scene::features` stay
  calibrated. `load(path)` decodes PNG and JPEG: enable `image`'s `jpeg` feature in `crates/core/Cargo.toml`. Restored
  and imported slides can be `.jpg`.
- `relate(a, b) -> Relation { changed, added, lost }`:
  - A pixel changes when it moves by more than ~24 levels, which stays clear of JPEG noise.
  - **added** = changed where `a` is flat (3×3 range < 12); **lost** = changed where `a` had structure.
  - Ignored on both sides: the PowerPoint toolbar zone (bottom-left), and the Zoom bar band when it matches the
    detector's bar rule (make `detect::bar_only` `pub(crate)`).
  - Ignored on the **lost side only**: cursor-sized components. Anything added always counts as content, so a filled-in
    digit or tick is never thrown away.
- Each relation is decided from these fractions:
  - **earlier state** `a ⊑ b`: lost ≤ L (start at 0.25 %) and added above a noise floor.
  - **same** `a ≡ b`: mutual ⊑, or changed below the noise floor.
  - **photographic**: soft ≥ 0.25 and dominant < 0.40.
  - **same_view**: changed < ~0.3.
  - Calibration (Verification 1) sets the final values.

### 2. Judging — `crates/core/src/session/tidy.rs` (new)
- The pure function `judge(slides, looks, scope, slide_index, pinned) -> Vec<Verdict { index, why: Redundant, noted }>`.
  It decides captures greedily from the most ink to the least, so a capture is never removed together with its keeper.
  - **Candidates** are auto, unpinned captures with a file on disk. Manual captures and pinned ones still count as keepers.
  - **⊑** compares against keepers within 10 min.
  - **≡** compares against any earlier capture of the lecture; a prefilter on the 144 tile means comes first, and the
    lower index is kept.
  - **Camera** is a run of ≥ 2 photographic captures whose neighbours are `same_view`. A lone photo slide stays.
- `pub enum Redundant { EarlierStateOf(u32), SameAs(u32), Camera }` implements `Display` for the notice text.
- `Tidier { cache: HashMap<String, Arc<Look>> }` is shared as `Arc<tokio::sync::Mutex<Tidier>>`.
  - `sweep(files, store, scope)` decodes and judges outside `Store::update` (in `spawn_blocking`).
  - Each removal then goes through the one writer, which checks again that the candidate is still pending and its keeper
    is still registered.

### 3. Removal plumbing — `session/slides.rs`, `session/sidecar.rs`
- Factor out `remove_in(files, sc, index, noted_ok)`; the existing `remove` wraps it. `noted_ok` is true only on the
  offline paths (after class, CLI).
- New `Sidecar.pinned_slides: Vec<u32>` (`serde(default)`, skipped when empty). `undo_remove` pins what it restores, so
  ⌘Z of an automatic removal is never undone by the next sweep.
- `Event::SlideRemoved { index, reason: Option<Redundant> }`:
  - wire `reason: Option<String>` with `skip_serializing_if`;
  - adapter notice: "Slide 199 removed: an earlier state of slide 200 · ⌘Z restores it";
  - `plain.rs` and `tui/state.rs` show the same text;
  - `wire.ts` gets an optional `reason`.

### 4. Hooks (`session/lecture.rs`)
1. **Live**: in `capture_task`, after `slides::register` returns an auto slide, run `sweep(Pending)`. Pass in the
   `snapshotting` flag and skip the sweep while it is set, because the next sweep catches up.
2. **Before every snapshot**: in `notes_worker`, before the flag is set (`lecture.rs:417`), skipped on `hurry`, and before
   the stop snapshot in `run()` (`lecture.rs:683-691`, offline store).
3. **After class**: in `polish_after`, between `folder::open` and `polish`, run `sweep(All)`. A redundant capture that is
   already used has its embed dropped (§5) before its file moves.
- Import and `slide_watcher` need no hook, because manual images are never candidates.

### 5. Notes edit for a used capture — `session/notesfile.rs`
`drop_embeds(files, sc, &[SlideEntry], at)`:
- It walks the lines with `embeds::repair`'s fence tracking and drops a line only when it is exactly one own-line
  `![Slide N](p)` resolving to that capture's file. Zero, several or inline copies are skipped and reported.
- It collapses doubled blank lines and drops an emptied `### Slides not placed`.
- It writes through the existing `notesfile::replace(files, sc, &new, &sha_before, at)` (`notesfile.rs:182`). That
  refuses an outside change, backs up to `.live_notes/<stem>_HHMMSS.md`, writes atomically and advances
  revision/len/sha256. Notes are edited first and files moved second.
- **Swap** `A=B` (Week 12 only, via the CLI): refused unless `A ⊑ B` and B is in `removed_slides`. It replaces A's embed
  line with B's in place, returns B's file to `slides/` under its own index (it is used, so not pending), pins B and
  removes A.

### 6. Camera latch — `capture/scene.rs` `Gate`
- Latch to Camera only on measured motion: a full set of `LOOKS` deltas with mean ≥ `MOTION` on a photographic frame.
  Stay Camera while frames remain photographic, even when still.
- Unlatch on a non-photographic frame or on a cut (one sample's mean change ≥ ~0.08, calibrated with
  `examples/scene_stats.rs`).
- The existing test `a_picture_that_holds_still_is_a_slide…` keeps passing, because a still photo with no motion never
  latches.

### 7. Cleanup after any complete page — `notes/archive.rs`, `session/lecture.rs`
- New `Lecture::after_page`, called from `page_after_polish` and from `page()`, so `lecture page` and the app's Open study
  page also clear once the page is complete. It does three things:
  1. the existing verified `archive::clear` of captures;
  2. deletes regular image files directly inside `slides/removed/`, checked the way `capture_path` checks paths, then
     removes the empty folder;
  3. with a sidecar present, no unresolved `gaps` and no session running, deletes the sidecar's `recordings/*.wav`, then
     the empty `recordings/`.
- `CapturesArchived` reports images, discarded images and recordings, with their bytes.
- Stop writing `removed-captures`: `page::render` (`page.rs:309-311`) and `archive::adopt` (`:194`). `render` keeps
  archived gallery images only for paths the notes still embed, so a removed slide cannot come back through
  `folder::open`'s archive recovery.
- `removed_slides` entries stay for number reservation (`folder.rs:186`). `undo_remove` on a cleared image fails with
  "its image was cleared after the study page".
- Check that `folder::open` and `lecture audit` tolerate deleted recordings, with a test.

### 8. CLI — `lecturelive lecture tidy` (`crates/cli/src/args.rs`, `crates/cli/src/lecture.rs`)
- It branches before the API-key lookup, the way `audit` does, and takes `FolderLock`. It finds the days through
  `.live_notes/*.v2.json` (as `audit_folder` does, `audit.rs:179`); a folder without a v2 sidecar is refused for
  judging.
- **Dry run by default.** It prints each verdict ("199 → earlier state of 200"), each kept capture that is an earlier
  state of a discarded one (the manual-mistake report), and the bytes it would clear.
- **`--apply`** does all of the following:
  - runs `sweep(All)` with the notes edits;
  - `--swap A=B` performs the swaps;
  - on a folder whose page is already complete, it strips the old `removed-captures` section (via `archive::with_removed`
    with an empty map) and runs §7's discarded-image and recordings deletion;
  - after notes edits on a finished page, it warns that the page is stale.
- Update the help goldens.
