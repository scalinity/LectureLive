Your two-hour lecture with LectureLive

One real Zoom lecture closes M6's gate. LectureLive runs beside your usual notes for two hours while five failures are caused on purpose, one at a time. Afterwards, one command checks that no audio went missing and none was recorded twice. The Python tool keeps taking your notes of record in its own folder, and nothing below touches it: it records BlackHole, its network is the real one, and its folder is not on the test disk. The same class closes the three lines left open since M0 and M1, and answers M5's full-screen question.

Before classabout 10 minutes

Plug in the receiver, open four Terminal windows, start LectureLive on a test disk

Zoom's Speaker stays on “LectureLive Loopback” (or wherever your notes already hear it), and the Mac's output on your headphones. Start the Python tool the way you always do, in its own folder. Then run the four windows below. In the app, choose the lecture folder on the test disk, choose Zoom and Wireless Mic Rx together (or Zoom through LectureLive Loopback if that choice is missing), and press Start. Answer Always Allow if the Keychain asks.

Commands

Terminal 1: the app's page server (leave it running)

cd "$HOME/Documents/Tools/LectureLive/apps/desktop" && npm run dev

Terminal 2: the forwarder that V10 stops (note the pid it prints)

cd "$HOME/Documents/Tools/LectureLive" && cargo run -q -p lecturelive-core --example netcut -- 127.0.0.1:8443 api.x.ai:443

Terminal 3: the test disk V13 fills, and the lecture folder on it

hdiutil create -size 2g -fs HFS+ -volname LLLecture "$HOME/Library/Application Support/LectureLive/m6-lecture.dmg"
hdiutil attach "$HOME/Library/Application Support/LectureLive/m6-lecture.dmg"
mkdir -p "/Volumes/LLLecture/<Course>/Weeks/<Week NN — Title>"

Terminal 4: the app, through the forwarder, recording what the slide detector sees

cd "$HOME/Documents/Tools/LectureLive"

  LECTURELIVE_RECORD="$HOME/Library/Application Support/LectureLive/m6-fixtures/zoom-live-$(date +%Y%m%d)" \
  ./target/debug/desktop

Keep one more Terminal free for the commands in V03, V10, V13 and V14.

Spec §10, “Network down / websocket error”: reconnects, the gap is recorded, recovered once online, and recording continues.

First the link drops with nothing passing, as Wi-Fi does; ten minutes later the connection is refused. Only LectureLive goes through the forwarder, so Zoom and your notes keep the network.

Commands and what to expect

At 0:45: connections are refused for 30 seconds

Press Ctrl-C in Terminal 2, wait 30 seconds, then run its command again.

Expected

  • The strip says “reconnecting”, then “transcribing” again.
  • The gap count rises, then falls to 0 as the gaps are recovered.
  • Zoom and the Python tool carry on as if nothing happened.

D2M4 open thread

Allow a production build, so the built app's security policy is checked

In development the page's content security policy comes from SvelteKit. In a built app it is SvelteKit's tag together with Tauri's header, and no run has checked that pair, because builds wait for your go-ahead. Say yes to let M6 build once and check it.

Answered yes on 26 September 2026. M6 built once, beside the canary without touching it, and the built app blocked exactly what development blocks while its slides still loaded.
